# 公開カタログ→API仕様書の初回ベンチマーク

実施日: 2026-10-25（Asia/Tokyo）。対象: https://hn.algolia.com/ 。
試行ID: `f42368ad-3251-4503-8f90-da0e568b657b`。条件は `benchmarks/public-hn.json`。

## 結果

公開済みのUnbrowseカタログ2資料から、Codex SDKで根拠付きの仕様書案を生成し、引用を機械検証して改訂1として保存できた。新規ブラウザ調査・学習・HTTP再実行は未実施。

| 資料 | 取得・保存時間 | JSON再直列化サイズ |
| --- | ---: | ---: |
| site catalog | 5,486 ms | 5,250 bytes |
| tool OpenAPI | 444 ms | 11,287 bytes |

上記はSDK呼び出しとローカル保存の時間。2呼び出し合計5,930ms。1試行だけなので速度の一般化やp95は出さない。JSONサイズは通信線上のbytes数ではなく、実際の保存ファイルは整形・秘密値除去によりサイズが変わる。対象SaaSへの通信数・費用は測れていない。

## 仕様化できた範囲と不足

| 事前評価項目 | Codexの評価案 |
| --- | --- |
| 対象自身のHTTPメソッド・パス | 未確認 |
| 入力名・型・制約 | 一部。tags/hitsPerPageという候補はあるが対象HTTP契約は未確認 |
| 応答構造と具体例 | 一部。派生schemaはあるが実HTTP本文はない |
| 認証・エラー条件の確認状態 | 一部。Unbrowse側の記載と対象側の未確認を区別 |
| UnbrowseのAPIと対象APIの区別 | 記述済み |

これは正答率・採用可否の自動判定ではなく、未レビューの評価案。保存済みの資料から引用が取れることを機械確認した。実装者も公開資料のendpointが `https://unbrowse.ai/api/v1/sites/hn.algolia.com/call/...` であることを確認した。これを対象サービス自身のHTTPパスへ転記できない。

**今回確認できたのは、既存カタログの取得と仕様化の下書きまで。公開カタログだけでは、対象SaaSの外部API仕様書を確定する根拠が不足する。** Unbrowse全体の収集能力が不足すると結論付ける試験ではない。

## 次の実測

同じ対象の小さな読取機能について、Unbrowseでブラウザ観測・学習を行い、harnessYaml/skillMd/Run/eventsの取得内容を比較する。特に元HTTPのURL・メソッド・入力・応答本文へ到達できるかを確認する。到達できなければ、不足の再現例として記録してHAR補完を検討する。全面的な自律探索や独自収集エンジンは先行実装しない。

Unbrowseアカウントの保存済み接続は見つからず、device loginは人による承認がないまま期限切れ。新規の認証付き調査は未実施。接続後は `bun run cli tools --json` でそのアカウントの利用可能なツールを確認する。
